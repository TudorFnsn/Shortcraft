## 2. How the routine works: DM master agent + specialist agents

The routine's main session is the **master agent**. It does not do the analysis itself. It reads this file, then splits the day into independent jobs and sends them to subagents in **one parallel batch**, then merges the results into one digest and at most one PR.

| Agent               | Job                                                                                                                                                                                                                                           | Reads                                                                                                |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Revenue analyst** | MRR, net MRR, plan mix, churn, trial → paid, failed payments, refunds, top-up share, ARPU. Proposes pricing, annual plans, upsell and dunning changes.                                                                                        | Stripe (`stripe_analytics`, `stripe_api_read`), `scripts/finance-report.mts`                         |
| **Cost auditor**    | Real spend per finished video by provider (script tokens, images, video seconds, voice characters, render), waste on failed jobs, measured vs catalog cost (`models.ts`), cost per credit.                                                    | Supabase `render_jobs.api_cost_usd`, `credit_transactions`; provider usage dashboards when reachable |
| **Vendor scout**    | Finds cheaper or better providers per slot (video, image, voice, script) and fresh techniques. Every candidate gets a price per finished 15s video, a quality note and a source link. Web search only, no integration without a smoke result. | Web                                                                                                  |
| **Infra auditor**   | Hosting and tooling bill: Vercel usage/charges, Supabase plan and usage, Sentry, Resend, ElevenLabs slots, domain. Flags plan downgrades and waste.                                                                                           | Vercel (`list_billing_charges`), Supabase advisors/logs, fixed costs in §3                           |
| **Growth-for-cash** | Ideas that raise revenue per visitor: pricing page, annual billing discount, trial length, credit packs, referral, win-back, affiliate. Small, testable, each with an expected € impact.                                                      | Metrics report, `TheMasterPlan.md` §6–7                                                              |
| **Implementer**     | Takes the single best approved item and builds it with tests (new catalog row, adapter, report). Runs the full bar below.                                                                                                                     | Repo                                                                                                 |

Master-agent rules:

1. **Read first:** `TheMasterPlan.md` §7 and §11, this file, `git log -20`, open and recent PRs (an item in an open PR is not available), and the last digest in §7 below.
2. **Always start with the numbers:** run `npx tsx scripts/finance-report.mts --json` if `.env.local` exists, otherwise use the Supabase and Stripe connectors (read-only). Put MRR, net MRR, 30-day API spend, cost per finished video and gross margin at the top of the digest, with the change since the last entry.
3. **Prioritise by cash:** rank every proposal by expected € per month, then by effort and risk. Cost cuts that need no customer-facing change come before price changes.
4. **One PR per run at most**, small and tested. Everything else goes into §5 as a ranked proposal.
5. **Evidence over snippets:** a price from a search snippet is a _candidate_, not a fact. A provider is only adopted after a measured smoke run (`scripts/live-providers-smoke.mts`) shows the real cost per 15s video. The margin gate (3x worst case) must still pass.
6. **Ask for what is missing.** If a data source is unreachable or a number needs the owner, say exactly what and how to provide it (§6), and notify.

**Bar for any PR:** `npm run format:check && npm run lint && npm run typecheck && npm test && npx next build` pass in mock mode, and `npx tsx scripts/margin-report.mts` still passes.

## 4. Baseline (measured 2026-10-14, read-only)

- Supabase `ShortCraft`: **6 profiles, 2 live subscriptions** (Stripe is **test mode only**: sandbox account `acct_1UKkSC0LHtTQ4zpU`, so there is **no real MRR yet**).
- `render_jobs`: **14 finished videos, $8.13 total API cost, $0.58 average**; 3 failed jobs, $0.00 cost (failures are refunded and cost nothing so far).
- Average $0.58 is far above the catalog's ~$0.07 for a 15s Standard video, so those jobs are mostly Premium or test runs. **First task for the cost auditor:** split cost by tier and provider, because the catalog's `costUsdPerUnit` is still researched, not measured.
- Margin gate (TheMasterPlan §7): passes. Starter 9.4x, Pro 3.00x, Ultra 3.23x, top-ups 4.0–5.9x. **Pro and Ultra sit right on the 3x line**, so any price cut or credit-scale change needs the gate re-run first.
